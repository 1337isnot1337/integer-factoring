# The exact finite divisor-count parameter

## Result and meaning

For `n>=1`, define

\[
D(n)=\max_{1\le N<2^n}\tau(N),\qquad
q_{\rm exact}(n)=\lceil\log_2 D(n)\rceil.        \tag{1}
\]

Both parameters, and a least witness attaining the maximum, can be computed
deterministically in

\[
2^{O(\sqrt n)}\operatorname{poly}(n)
\]

bit time by enumerating nonincreasing prime-exponent vectors.  A streamed
implementation uses `O(sqrt(n) log(n+2))` working bits, excluding the input
and streamed output.  The supplied fast implementation uses ordinary
integer arithmetic and polynomial workspace; its multiplication-bit
primitive is separately checked against Python integers.

The quantity in (1) is the **smallest valid integer exponent** in a bound
`tau(N)<=2^q` that depends only on the bit bound `n`.  In particular,

\[
q_{\rm exact}(n)\le q_*(n)
\]

for the explicit split bound in
[the optimized divisor-count note](optimized-divisor-count-bound.md).  This is a finite-parameter improvement,
not an improvement of the unconditional factoring exponent.  The exact
oracle costs more preprocessing than that note's logarithmic-space,
polynomial-in-`log n` formula.

All prime and partition estimates needed below are proved here.  No prime
number theorem, prime asymptotic, or partition asymptotic is assumed.

## 1. Canonical exponent vectors suffice

Let `p_1<p_2<...` be the primes.  If an integer has positive prime exponents
whose multiset is `{e_1,...,e_k}`, its divisor count is `prod_i(e_i+1)`.
For a fixed multiset this count does not change when the exponents move.

Moving the prime factors to the first `k` primes cannot increase the integer.
Sorting the exponents so that

\[
e_1\ge e_2\ge\cdots\ge e_k\ge1
\]

cannot increase it either: if `p<q` and `a>b`, then
`p^a q^b <= p^b q^a`, since their ratio is `(p/q)^(a-b)`.
Therefore every divisor count realized below `2^n` is realized by a
canonical integer

\[
M(e)=\prod_{i=1}^k p_i^{e_i}<2^n.               \tag{2}
\]

Since every prime is at least 2, (2) implies

\[
\sum_i e_i\le n-1.                              \tag{3}
\]

Thus it is enough to enumerate the empty vector and every integer partition
of every total at most `n-1`.  Reject the vectors whose canonical integer
is at least `2^n`, and maximize `prod_i(e_i+1)` among the rest.
Ties can be broken by the canonical integer itself.  The rearrangement
argument also proves that the least witness found this way is the least
integer witness globally.

## 2. Polynomial prime generation, with an elementary proof

For every positive integer `m`,

\[
\binom{2m}{m}=\prod_{j=1}^m\frac{m+j}{j}\ge2^m.
\]

For a prime `p`, Legendre's factorial formula gives

\[
v_p\binom{2m}{m}
=\sum_{a\ge1}\left(\left\lfloor\frac{2m}{p^a}\right\rfloor
 -2\left\lfloor\frac m{p^a}\right\rfloor\right)
\le\lfloor\log_p(2m)\rfloor.
\]

Each summand is zero or one.  Consequently

\[
2^m\le\binom{2m}{m}\le(2m)^{\pi(2m)},\qquad
\pi(2m)\ge\frac m{\log_2(2m)}.                  \tag{4}
\]

Set `m=2k^2`.  The elementary inequality `2^(k-1)>=k` implies
`log_2 k<=k-1`, so

\[
\pi(4k^2)\ge\frac{k^2}{1+\log_2 k}\ge k.       \tag{5}
\]

In particular, the first `n` primes lie below `4n^2`.  A sieve through
that bound has polynomial bit cost and `O(n^2)` storage.  When small
workspace is preferred, the `i`th prime can instead be regenerated by
trial scanning candidates at most `4n^2` and trial divisors at most `2n`.
That takes polynomial time and `O(log n)` working bits.  No primality oracle
or prime table is assumed.

## 3. How many patterns are enumerated?

Let `p(s)` be the number of integer partitions of `s`.  For any `eta>0`,
the usual product expansion, obtained by choosing the multiplicity of
each possible part, gives

\[
\sum_{s=0}^{N}p(s)
\le e^{\eta N}\prod_{j\ge1}(1-e^{-\eta j})^{-1}.
\]

Its logarithm is bounded using nonnegative convergent series:

\[
\begin{split}
\log\prod_{j\ge1}(1-e^{-\eta j})^{-1}
&=\sum_{a\ge1}\frac1{a(e^{\eta a}-1)}\\
&\le\frac1\eta\sum_{a\ge1}\frac1{a^2}
\le\frac2\eta.
\end{split}
\]

The final estimate follows from comparison with the integral of `x^-2`
over `[1,infinity)`.  Taking `eta=sqrt(2/N)` gives, for `N>=1`,

\[
\sum_{s=0}^{N}p(s)\le\exp(2\sqrt{2N}).          \tag{6}
\]

This proves the needed `2^O(sqrt(n))` pattern count directly.  The case
`n=1` consists only of the empty partition.

A depth-first enumeration uses positive multiplicities of strictly
decreasing part sizes.  Each node is itself one partition of total at
most `n-1`, so the number of nodes is bounded by (6).  Each node has only
polynomial bookkeeping and arithmetic in the fast implementation.

## 4. Full bit costs, including rejected candidates

### Fast ordinary-integer implementation

Generate the first `n-1` primes, then extend exponent prefixes subject to
nonincrease and (3).  Multiply the current canonical integer by the next
prime incrementally, stopping an exponent loop once the value reaches
`2^n`.  Prefixes are checked as possible candidates, so no trailing zero
exponents are needed.  Divisor counts are updated by the factor `e_i+1`.

Accepted prefix products have at most `n` bits; the first rejected product
has at most `n+O(log n)` bits.  Every divisor product has at most `n` bits
because `e+1<=2^e`.  Standard exact arithmetic therefore costs polynomial
time per enumerated node.  Together with (5)--(6), the total bit time is
`2^O(sqrt(n)) poly(n)`.  The sieve and ordinary recursion use polynomial
workspace.  This is the implementation in `exact_divisor_maximum.py`.

### A lower-space implementation

The following refinement avoids storing an `n`-bit candidate product.
Store a partition as pairs `(part size, positive multiplicity)` with
strictly decreasing sizes.  If it has `s` distinct sizes, then
`s(s+1)/2<=n-1`.  Both the current partition and the best partition found
so far therefore require only `O(sqrt(n) log n)` bits.  The depth-first
enumeration stack has the same bound.  Retain the best **partition**, not
its integer product or divisor count.

For a candidate partition, view (2) as a product of at most `n-1` prime
factors, with repetition.  Any requested leaf factor is found from the
compressed exponent vector and regenerated by the trial-prime procedure
after (5).  The divisor count is likewise a product of at most `n-1`
factors `e_i+1`, each obtainable from the compressed vector.

Crucially, every candidate, including those later rejected, has a common
product-bit bound

\[
B=(n-1)\lceil\log_2(4n^2)\rceil+1=O(n\log n), \tag{7}
\]

because its total prime multiplicity is at most `n-1`.  The divisor count
has the sharper bound `n` bits.  No feasibility test is assumed when (7)
is used.

To obtain a product bit, split the factor interval in half recursively.
For two child products `A,B`, compute the requested bit `k` by streaming
**every column from zero through k**.  Start with carry zero and use

\[
c_j=\mathrm{carry}_j+\sum_{i=0}^j A_iB_{j-i},\qquad
\mathrm{bit}_j=c_j\bmod2,\qquad
\mathrm{carry}_{j+1}=\lfloor c_j/2\rfloor.       \tag{8}
\]

There are at most `B` summands per column.  The carry is at most `B`, by
induction, so each recursion frame needs `O(log B)` bits for its counters,
partial sum, carry, and interval endpoints.  The balanced recursion has
depth `O(log n)`, hence uses `O(log^2 n)` auxiliary space.  It stores no
partial product and uses no memoization.

At each level there are at most `O(B^2)` recursive bit requests.  Including
polynomial-time leaf generation, one requested bit therefore costs

\[
(B^{O(1)})^{O(\log n)}\operatorname{poly}(n)
=2^{O(\log^2 n)}.
\]

Check `M(e)<2^n` by checking that every bit from position `n` through the
bound (7) is zero.  Compare two divisor counts by scanning their at most
`n` bits from high to low; in a tie, compare canonical products the same
way.  None of these operations stores the product.  Update only the
compressed best partition.  The winning integer and divisor count can
be written to the output one bit at a time if requested.

Multiplying this cost by (6) gives

\[
2^{O(\sqrt n+\log^2 n)}=2^{O(\sqrt n)},
\]

with total workspace `O(sqrt(n) log(n+2))`.  This is asymptotically
`o(n/log n)`, so the exact parameter can be computed within the existing
sublinear-space envelope without relying on the polynomial-space fast
implementation.  The preprocessing time is also below the existing
factoring time scale.  No factoring score improvement follows.

The supplied `streamed_product_bit` implements the arithmetic primitive
(8).  The complete compressed-partition low-space search is specified by
the construction above; the practical oracle uses the faster ordinary
integer search.

## 5. Finite optimality and recovery parameters

Exact arithmetic gives:

| Input bound `n` | `D(n)` | Exact `q` | Earlier split `q_*` | Least maximizing integer |
|---:|---:|---:|---:|---:|
| 8 | 20 | 5 | 5 | 240 |
| 16 | 120 | 7 | 9 | 55440 |
| 32 | 1920 | 11 | 17 | 3491888400 |
| 64 | 184320 | 18 | 33 | 18401055938125660800 |
| 128 | 318504960 | 29 | 65 | 278282512406132373381723386382308832000 |

The exact cap `D(n)`, rather than merely `2^q`, may also be used directly
as a support bound.  For example, the ternary singleton-bucket degree can
use the least positive `k` with `3^k>n(D(n)-1)`.

For exact count recovery modulo a power of two, retain the strict inequality:
the least exponent `b` with `2^b>D(n)` is

\[
b=\lfloor\log_2 D(n)\rfloor+1.
\]

This equals `q_exact` unless `D(n)` is a power of two, in which case it
equals `q_exact+1`.  In particular, the `n=1` case has `D=1,q=0,b=1`.
The distinction must not be lost when replacing the older safe modulus.

## 6. The leading auxiliary asymptotic also remains one

For completeness, the same elementary prime argument supplies the needed
lower bound, without a prime asymptotic.  Let `delta=log_2(4k)>=2` and choose
a power of two `x` with `4k delta<=x<8k delta`.  It is automatically even. Since
`log_2 x<=delta+log_2 delta+1<=2delta`, equation (4) gives `pi(x)>=k`.
Thus

\[
p_k\le8k\log_2(4k).                              \tag{9}
\]

For `n>=2`, put `L=ceil(log_2 n)`,
`d=L+ceil(log_2(L+2))+4`, and `k=floor((n-1)/d)`.
When `k>=1`, (9) gives `p_k<2^d`, so the product of the first `k` primes
is below `2^n` and has `2^k` divisors.  Therefore

\[
q_{\rm exact}(n)\ge
\left\lfloor\frac{n-1}{\lceil\log_2 n\rceil+
 \lceil\log_2(\lceil\log_2 n\rceil+2)\rceil+4}\right\rfloor.
\]

Combining this with `q_exact<=q_*` and the already proved upper asymptotic
for `q_*` yields

\[
q_{\rm exact}(n)=(1+o(1))\frac n{\log_2 n}.
\]

The gain in the table is exact finite optimization, not a smaller leading
asymptotic coefficient.

## Reproduction

```sh
python tools/check_exact_divisor_maximum.py
python tools/check_exact_divisor_maximum.py --large
python tools/exact_divisor_maximum.py 32 64 128
```

The checker independently counts every positive divisor of all integers
from 1 through 262143, and compares exact maxima and least witnesses for
all 18 complete bit ranges.  It also checks the first 64 generated primes
by trial division, checks 90 streamed product bits against ordinary integer
products, verifies all reported witness factorizations and parameter
comparisons, and rejects invalid inputs.  The optional large run includes
the 128-bit maximum and took about seven seconds in the recorded session.
